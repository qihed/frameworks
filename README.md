# Сервис учёта комиксов

**Репозиторий:** https://github.com/qihed/frameworks

## Назначение

Консольное приложение для ведения личной коллекции комиксов. Сервис
позволяет пользователям просматривать доступные серии, добавлять их в
свою коллекцию, отслеживать статус и прогресс чтения, а также хранить
эти данные между запусками программы.

Решаемая задача: у читателя комиксов коллекция растёт и разрастается по
разным сериям, из-за чего он теряет представление о том, что уже
прочитано, что отложено, а что стоит начать читать. Сервис собирает эти
сведения в одном месте и позволяет вести учёт нескольким пользователям.

## Целевая аудитория

Читатели и коллекционеры комиксов, манги и графических романов, которые
следят сразу за несколькими сериями и хотят вести учёт собственной
коллекции.

## Предметная область

Основными объектами предметной области являются:

* **серия** — цикл комиксов с названием, издателем, автором, общим
  числом выпусков и возрастным ограничением;
* **пользователь** — читатель, ведущий собственную коллекцию;
* **запись коллекции** — связь пользователя и серии: статус чтения,
  количество прочитанных выпусков и признак удаления записи.

Пользователь может добавить серию в свою коллекцию, если она ещё не
добавлена активной записью и его возраст не меньше возрастного
ограничения серии. Удалённая из коллекции запись не удаляется
физически, а помечается как неактивная и не блокирует повторное
добавление серии.

## Основные сущности

### Series — серия (`models/series.py`)

Атрибуты: `id`, `title`, `publisher`, `author`, `issues_total`,
`age_limit`.

Методы:

* `is_suitable_for(user_age)` — проверка доступности серии по возрасту;
* `validate_age_limit(age_limit)` — проверка корректности значения
  возрастного ограничения (`@staticmethod`);
* `__str__()` — строковое представление серии.

### User — пользователь (`models/users.py`)

Атрибуты: `id`, `name`, `age`, `email`.

Методы:

* `from_data(data)` — создание пользователя из словаря, например из
  JSON (`@classmethod`);
* `__str__()` — строковое представление пользователя.

### CollectionEntry — запись коллекции (`models/collection.py`)

Атрибуты: `id`, `series` (объект `Series`), `user` (объект `User`),
`status_code`, `issues_read`, `is_removed`.

Методы:

* `remove()` — отметить запись как удалённую из коллекции;
* `calculate_progress()` — прогресс чтения серии в процентах;
* `count_issues_left()` — сколько выпусков серии осталось прочитать;
* `status` — текстовый статус записи с учётом отметки об удалении
  (`@property`, вызывается без скобок: `entry.status`);
* `__str__()` — строковое представление записи.

Функция `get_status_name()` перенесена из начального сценария ПР1 без
изменения назначения.

## Взаимодействие объектов

```text
User
 └── создаёт → CollectionEntry
                    │
                    ├── user  → User
                    └── series → Series
```

Запись `CollectionEntry` хранит ссылки на объекты `Series` и `User`, а
не только их идентификаторы, поэтому связанные данные доступны
напрямую: `entry.series.title`, `entry.user.name`.

## Основные операции

### Работа с сериями

* добавление серии (`add_series`);
* поиск серии по названию (`find_series`, `find_series_by_id`);
* проверка возрастного доступа (`check_series_age_limit`);
* фильтрация по возрастному ограничению (`filter_series_by_age_limit`);
* сортировка по количеству выпусков (`sort_series_by_issues`);
* просмотр списка серий (`show_series`).

### Работа с пользователями

* добавление пользователя (`add_user`);
* поиск пользователя по идентификатору или подстроке имени/почты
  (`find_user_by_id`, `find_user`);
* просмотр списка пользователей (`show_users`).

### Работа с коллекцией

* добавление серии в коллекцию пользователя с проверкой доступности
  (`add_to_collection`, `is_series_in_collection`);
* обновление прогресса чтения (`update_issues_read`);
* удаление (отмена) записи коллекции — вызывает `entry.remove()`
  (`remove_from_collection`);
* просмотр записей коллекции (`show_collection`).

При добавлении в коллекцию проверяется, что серия ещё не добавлена
активной записью этого пользователя и что его возраст соответствует
возрастному ограничению серии.

### Декоратор журналирования

Модуль `decorators.py` содержит декоратор `log_action`, который выводит
сообщение о вызове пользовательского сценария перед его выполнением.
Декоратор построен на `*args`/`**kwargs` и `functools.wraps` и применён
в `main.py` к сценариям добавления и удаления записи коллекции.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

* `data/series.json`;
* `data/users.json`;
* `data/collection.json`.

Формат хранения не изменился по сравнению с ПР2, изменился способ
загрузки и сохранения: модуль `storage.py` преобразует JSON в объекты
классов `Series`, `User` и `CollectionEntry` при загрузке, а при
сохранении — объекты обратно в словари. Связи `CollectionEntry.series`
и `CollectionEntry.user` при сохранении заменяются идентификаторами
`series_id` и `user_id`, а при загрузке восстанавливаются поиском
объектов в уже загруженных коллекциях `series_list` и `users`.

Отсутствие файла или повреждённые данные не приводят к аварийному
завершению программы: обрабатываются исключения `FileNotFoundError` и
`json.JSONDecodeError`. Некорректный ввод пользователя обрабатывается
функциями модуля `utils.py`, которые повторяют запрос до получения
корректного значения.

## Назначение модулей

* `main.py` — точка входа: главное меню и пользовательские сценарии;
  работает с объектами `Series`, `User` и `CollectionEntry`, не хранит
  коллекции словарей;
* `models/series.py` — класс `Series` и функции работы с коллекцией
  серий;
* `models/users.py` — класс `User` и функции работы с коллекцией
  пользователей;
* `models/collection.py` — класс `CollectionEntry` и функции работы с
  записями пользовательской коллекции;
* `storage.py` — загрузка и сохранение данных: преобразование
  JSON ↔ объекты Python;
* `utils.py` — безопасный ввод целых чисел, дат и непустых строк;
* `decorators.py` — декоратор `log_action` для журналирования
  пользовательских сценариев;
* `tests/` — автоматизированные тесты `pytest`.
